# ID Service Specification

## ADDED Requirements

### Requirement: The system SHALL provide a unified ID service

All new business modules SHALL request IDs through `IdService` instead of instantiating ID generators directly.

#### Scenario: Generate comment ID

- **WHEN** the comment module needs a new `comment_id`
- **THEN** it requests an ID from `IdService` using the `comment` namespace
- **AND** the returned ID is generated by Snowflake

### Requirement: Snowflake SHALL serve high-throughput business entities

Snowflake SHALL be used for content and event IDs that need high concurrency and rough time ordering.

#### Scenario: Generate publish attempt ID

- **WHEN** a publish attempt is created
- **THEN** `IdService` returns a Snowflake ID

### Requirement: Segment SHALL serve low-frequency operational records

Segment mode SHALL be used for low-frequency operational records that benefit from controllable ranges.

#### Scenario: Generate reconciliation task ID

- **WHEN** a reconciliation task is created
- **THEN** `IdService` uses the `reconciliation_task` Segment biz tag

### Requirement: User IDs SHALL remain unchanged

The system SHALL NOT change the current user ID generation strategy in this change.

#### Scenario: Register user

- **WHEN** a new user registers
- **THEN** the existing user ID behavior remains unchanged
